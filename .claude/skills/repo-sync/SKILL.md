# repo-sync

## 1. 검증된 절차 (표현을 바꾸지 않고 그대로 안내)

1. 기존 파일 교체: GitHub에서 파일 열기 → 연필 아이콘 → 편집창 클릭 → Ctrl+A → Delete → 교체본 붙여넣기 → Commit changes.
2. 새 파일: Add file → Create new file → 경로 입력. `/`가 있으면 폴더가 자동 생성된다(`.claude/...` 포함).
3. 삭제: 파일 열기 → 오른쪽 위 ⋯ → Delete file → Commit changes.
4. 웹 편집기용 출력 형식: 파일마다 "경로 + 전체 교체본". 바깥 코드블록은 백틱 4개.
5. 웹 편집기용은 한 번에 2개 파일 이하. 사용자가 승인한 구조 개편만 예외.
6. 사용자가 "덮어썼다"고 하면 다시 읽어 검증하지 않는다. 검증은 사용자가 요청할 때만 한다.
7. 커밋 직후 raw 주소는 캐시 때문에 몇 분간 옛 내용을 보여줄 수 있다.
8. 기본 반영 수단은 3장 opus-safe 모듈이다. 웹 편집기는 모듈을 쓸 수 없을 때만 쓴다.

## 2. 금지

| 방법 | 이유 |
|---|---|
| "찾아서 끼워 넣기" 부분 수정 지시 | 위치를 찾지 못해 실패 (2026-11-09) |
| opus-safe 모듈을 거치지 않은 스크립트 | 도구 선택 오류, 인코딩, 인용부호, 백업 누락으로 수십 회 실패 (E02~E09) |
| PowerShell `-replace`, 정규식, 줄 단위 치환으로 문서 수정 | 줄바꿈·인코딩 차이로 한글 전체가 깨져 복원 불가 (E05) |
| 기억으로 쓴 찾을 원문 | 띄어쓰기 하나만 달라도 0회 일치. 그 세션에 읽은 원문에서 복사한다 |
| 채팅에 주는 스크립트 안에 백틱 3개 코드펜스 | 채팅 화면이 코드 블록 끝으로 인식해 복사가 중간에 끊김 (E14) |
| Claude Code 에이전트 | 정액제 한도 소진 |
| API 종량제 | 요금 예측 불가 |

## 3. opus-safe 모듈 (기본 반영 수단)

- 모듈: `tools/opus-safe.ps1`. ASCII 전용이며 한글을 넣지 않는다(PowerShell 5.1이 BOM 없는 UTF-8 파일을 ANSI로 읽기 때문).
- 로컬 저장소: `E:\opus-git`. 사용자 PC는 PowerShell 5.1.
- 시험 이력: 2026-11-09 1차 `.gitattributes` 생성 OK(2c2a709 -> 344cbc9), 모듈 등록 OK(344cbc9 -> 494e820), 한글 부분 수정(이 장 개정 자체).

### 3-1. AI 규칙

1. 모듈 코드를 스크립트에 다시 쓰지 않는다. 3-2 호출 틀만 출력한다.
2. 찾을 원문은 그 세션에 raw 주소로 읽은 내용에서 그대로 복사한다. 기억으로 쓰지 않는다.
3. 찾을 원문은 파일에서 정확히 1번만 나오도록 앞뒤 줄을 포함한다.
4. 내용에 줄 맨 앞 here-string 끝 표시가 있으면 임시 표식으로 쓰고 호출 전에 `.Replace()`로 되돌린다.
5. 커밋 메시지는 영어로 쓴다(5.1의 외부 명령 인자 한글 처리 미검증).
6. 전체 교체(`-Files`)는 새 파일, 150줄 이하 문서, 변경이 3분의 1을 넘을 때만 쓴다.
7. 한글이 들어가는 호출에는 `-Canary '가'`를 반드시 붙인다.
8. 사용자는 `OK` 또는 `FAIL`/`RESTORE` 줄만 붙인다. 다른 출력을 요구하지 않는다.
9. 스크립트 안에는 백틱 3개 코드펜스를 넣지 않는다. 문서 속 코드 블록은 `~~~`로 쓴다. 채팅 출력의 바깥 블록은 백틱 4개로 감싼다.
10. 사용자가 붙여넣은 뒤 `>>`에서 멈추면 Ctrl+C로 취소하게 한다. 스크립트가 끝까지 복사되지 않은 것이며 아무것도 바뀌지 않았다.

### 3-2. 호출 틀

~~~powershell
& {
. ([scriptblock]::Create([System.IO.File]::ReadAllText('E:\opus-git\tools\opus-safe.ps1')))
$E = New-Object System.Collections.ArrayList
$o = @'
찾을 원문
'@
$n = @'
바꿀 내용
'@
[void]$E.Add(@{ Path = '경로'; Old = $o; New = $n })
Invoke-OpusSafe -Repo 'E:\opus-git' -Commit 'English message' -Edits $E -Canary '가'
}
~~~

### 3-3. 장치와 막는 오류

| 장치 | 막는 오류 |
|---|---|
| `& { }`로 전체를 먼저 해석 | E06·E14 인용부호가 깨지거나 복사가 끊기면 한 줄도 실행되지 않음 |
| `-Canary '가'` | E02·E03 붙여넣기 중 한글 깨짐 |
| 메모리 선적용, 0회·2회 이상 일치 시 중단 | E05·E06 엉뚱한 곳 수정, 일부만 반영 |
| 기존 줄바꿈 유지, UTF-8(BOM 없음), 재독·U+FFFD 검사 | E03·E05 |
| 미커밋 변경 거부, 시작 커밋 기록, RESTORE 출력 | E07 백업 망각 |
| OK·FAIL 한 줄, git 메시지 앞 300자 | E08·E12 |
| 모듈 파일 하나로 고정 | E09 AI가 틀을 변형하거나 원칙을 잊음 |

## 4. 알려진 함정 (일반 지식, 이 환경에서는 미검증)

| 함정 | 증상 | 피하는 법 |
|---|---|---|
| Windows PowerShell 5.1의 `>`, `Out-File`, `Set-Content` | UTF-16 또는 CP949로 저장되어 한글이 깨짐 | `[IO.File]::WriteAllText(경로, 내용, (New-Object Text.UTF8Encoding $false))` |
| 콘솔에 한글 긴 텍스트 붙여넣기 | 코드페이지 949에서 깨지거나 잘림 | 붙여넣기 대신 파일로 저장 후 실행 |
| 큰따옴표 here-string `@" "@` | `$`, 백틱이 해석되어 내용이 바뀜 | 작은따옴표 here-string `@' '@` |
| here-string 끝 표시 | `'@`가 줄 맨 앞이 아니면 문법 오류 | 끝 표시는 줄 맨 앞 |
| 실행 정책 | `.ps1` 실행 차단 | 사용자 범위 정책 확인 |
| Python `open()` 인코딩 미지정 | Windows 기본값 CP949로 깨짐 | `encoding="utf-8"` 항상 명시 |
| Git `core.autocrlf` | 모든 줄이 변경된 것으로 표시 | `.gitattributes`로 줄바꿈 고정 |
| 채팅 코드블록 중첩 | 문서 안의 ``` 때문에 바깥 블록이 끊김 | 바깥 블록은 백틱 4개 |
