# repo-sync

## 1. 검증된 절차 (표현을 바꾸지 않고 그대로 안내)

1. 기존 파일 교체: GitHub에서 파일 열기 → 연필 아이콘 → 편집창 클릭 → Ctrl+A → Delete → 교체본 붙여넣기 → Commit changes.
2. 새 파일: Add file → Create new file → 경로 입력. `/`가 있으면 폴더가 자동 생성된다(`.claude/...` 포함).
3. 삭제: 파일 열기 → 오른쪽 위 ⋯ → Delete file → Commit changes.
4. AI의 출력 형식: 파일마다 "경로 + 전체 교체본". 바깥 코드블록은 백틱 4개.
5. 한 번에 2개 파일 이하. 사용자가 승인한 구조 개편만 예외.
6. 사용자가 "덮어썼다"고 하면 다시 읽어 검증하지 않는다. 검증은 사용자가 요청할 때만 한다.
7. 커밋 직후 raw 주소는 캐시 때문에 몇 분간 옛 내용을 보여줄 수 있다.

## 2. 금지

| 방법 | 이유 |
|---|---|
| "찾아서 끼워 넣기" 부분 수정 지시 | 위치를 찾지 못해 실패 (2026-11-09) |
| PowerShell·Python 번들 스크립트 자동 반영 | 도구 선택 오류, 도구 자체 에러, 인코딩 문제로 수십 회 실패 |

## 3. 스크립트 방식을 다시 검토할 수 있는 조건 (모두 충족 시)

1. 사용자가 먼저 요청한다.
2. 4장의 함정에 모두 대응한 절차다.
3. 파일 1개로 시험해 성공한 뒤 5장에 기록한다.

## 4. 알려진 함정 (일반 지식, 이 환경에서는 미검증)

| 함정 | 증상 | 피하는 법 |
|---|---|---|
| Windows PowerShell 5.1의 `>`, `Out-File`, `Set-Content` | UTF-16 또는 CP949로 저장되어 한글이 깨짐 | `[IO.File]::WriteAllText(경로, 내용, (New-Object Text.UTF8Encoding $false))` |
| 콘솔에 한글 긴 텍스트 붙여넣기 | 코드페이지 949에서 깨지거나 잘림 | 붙여넣기 대신 파일로 저장 후 실행 |
| 큰따옴표 here-string `@" "@` | `$`, 백틱이 해석되어 내용이 바뀜 | 작은따옴표 here-string `@' '@` |
| here-string 끝 표시 | `'@`가 줄 맨 앞이 아니면 문법 오류 | 끝 표시는 줄 맨 앞 |
| 실행 정책 | `.ps1` 실행 차단 | 사용자 범위 정책 확인 |
| Python `open()` 인코딩 미지정 | Windows 기본값 CP949로 깨짐 | `encoding="utf-8"` 항상 명시 |
| Git `core.autocrlf` | 모든 줄이 변경된 것으로 표시 | `.gitattributes`로 줄바꿈 고정 |
| 채팅 코드블록 중첩 | 문서 안의 ``` 때문에 바깥 블록이 끊김 | 바깥 블록은 백틱 4개 |
