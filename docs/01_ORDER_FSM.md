# 01 ORDER FSM — 주문 상태기계 완전 전이표

버전: v2 (2026-11-09)
관련 불변식: I3, I4, I5, I6, I7, I9, I10, I11, I12

## 0. 범위와 전제

- 대상: 신규 매수·매도 주문 1건의 일생. 정정 주문은 범위 밖이다(취소 후 신규로 처리).
- 주문 상태의 쓰기 주체는 OrderGateway 액터 1개다(I9). 전략은 "의도"만 제출하고 주문 상태를 직접 바꾸지 않는다.
- 최악 가정: 메시지 뒤바꿈, 중복, 유실, 임의 시점 크래시가 언제든 일어난다.
- 클라이언트 주문 ID는 없다고 가정한다. 키움 주문번호는 접수 응답을 받은 뒤에야 알 수 있다.

## 1. 주문 기록 (OrderRecord)

| 필드 | 의미 |
|---|---|
| intentKey | 전략 + 종목 + 봉ID + 방향. 전송은 키당 최대 1회 (I3) |
| strategy, symbol, side | 전략, 종목, 매수/매도 |
| purpose | 진입 / 청산 |
| qty, priceType, price | 주문 수량, 주문 유형, 가격 |
| env, account | 모의/실전, 계좌. 세션과 다르면 게이트가 거절 (I1) |
| state | 2장의 상태 |
| orderNo | 브로커 주문번호. 접수 전에는 없음 |
| cumQ | 지금까지 반영한 누적 체결량 (단조 증가, I5) |
| cancelPending | S/U 상태에서 받은 취소 요청 예약 플래그 |
| cancelTries | 취소 전송 횟수 |
| tokenGen | 전송 때 쓴 토큰 세대 (02 문서 T2, T3) |
| stateEpoch | 상태에 들어갈 때마다 +1. 오래된 타이머를 판별하는 데 씀 |
| sentAt | 전송 시각 (단조 시계, I12) |
| reason | 종료·HALT 사유 |

## 2. 상태

| 기호 | 상태 | 종료 | 노출 계산에 포함 |
|---|---|---|---|
| P | 저널에 의도 기록, 아직 전송 안 함 | 아니오 | 예 (예약 노출) |
| S | 전송함, 응답 대기 | 아니오 | 예 (전량) |
| U | 결과 모름 | 아니오 | 예 (전량 체결 가능성으로 계산) |
| A | 접수됨, 미체결 잔량 있음 | 아니오 | 예 (잔량) |
| C | 취소 요청 중 | 아니오 | 예 (잔량) |
| F | 전량 체결 | 예 | 아니오 |
| X | 취소 완료 (일부 체결 포함 가능) | 예 | 아니오 |
| R | 거부 또는 미접수 확정 | 예 | 아니오 |

종료 상태라도 늦은 체결은 반영한다(5장 F, X, R 행). "종료"는 더 이상 주문을 보내지 않는다는 뜻이지, 포지션이 확정됐다는 뜻이 아니다.

| 구분 | 사건 | 의미 |
|---|---|---|
| 외부 | 전송 | 입장 게이트가 주문을 네트워크로 넘김 |
| 외부 | REST 성공 | 주문번호가 들어 있는 접수 응답 |
| 외부 | 타임아웃·통신오류 | 응답 기한 Tr 초과, 연결 오류, 주문 요청에 대한 8005 |
| 외부 | 명시적 거부 | 브로커가 거부 코드를 반환. C 상태에서는 취소 요청에 대한 거부 |
| 외부 | 체결 통보(누적 q) | WS 체결 통보. q는 해당 주문번호의 누적 체결량 (7장 O4) |

| 제어 | 모드 하향 | ARMED에서 DEGRADED 또는 SAFE로 내려감 |
| 제어 | 진입 마감·강제청산 시각 | 당일 신규 진입 마감, 장 마감 전 강제청산 시각 |
| 제어 | 종목 HALT | 해당 종목의 상태를 믿을 수 없게 됨 |

## 4. 저널(WAL) 규칙

- J1: 의도를 받아들이면 P를 기록한다.
- J2: 네트워크로 넘기기 직전에 S를 기록하고, fsync가 끝난 뒤에 넘긴다. 그래서 "S 기록 없음"은 "전송 안 함"을 뜻한다.
- J3: 모든 전이는 저널에 먼저 기록한 뒤 메모리에 적용한다.
- J4: 재시작하면 저널을 재생한다. P만 있는 주문은 R(미전송 확정)이 되고, S 또는 U인 주문은 U가 되며, A와 C는 유지한 채 대조를 실행한다. 대조가 끝나기 전까지 모드는 ARMED가 될 수 없다(I11).
- J5: 저널 쓰기가 실패하면 신규 진입 의도를 금지한다. 청산 의도는 기록하지 못하더라도 사람에게 알람을 보낸다.
- 의도키는 P가 기록되는 순간 소모된다. 같은 키로는 다시 의도를 만들 수 없다(I3).

## 5. 완전 전이표

규칙: 빈칸은 없다. 일어날 수 없어야 하는 칸은 "HALT"로 정의한다. HALT가 발동하면 해당 종목은 자동 신규 주문이 전부 금지된다(청산 포함). 다만 노출을 줄이는 취소는 허용한다. 알람을 내고, 해제는 사람만 한다. 상태를 믿을 수 없을 때 새 주문을 내면 과매도가 생길 수 있기 때문이다.

### 5-2. 타이머

| 타이머 | 시작 | 해제 | 만료 시 동작 |
|---|---|---|---|
| 응답 기한 Tr | S 진입 | S 이탈 | "타임아웃" 사건 발생 → U |
| 대조 창 W | U 진입 | U 이탈 | 그동안 주기 Pq로 반복한 대조에서 끝까지 없으면 "대조: 없음" 사건 발생 → R |
| 취소 기한 Tc | C 진입, 취소 재전송 | C 이탈 | 대조 조회. 잔량이 있으면 취소 재전송(O5, 최대 K회), K회를 넘으면 HALT |
| 고아 만료 To | 고아 항목 생성 | 항목 적용 | 6장 규칙 |

타이머 사건은 (주문, stateEpoch)를 함께 싣고 다닌다. 현재 stateEpoch와 다르면 오래된 타이머이므로 폐기한다. 상태가 이미 바뀐 뒤에 늦게 터진 타이머가 엉뚱한 전이를 일으키지 못하게 하기 위해서다.

## 6. 고아 버퍼 (전역, 주문번호 기준)

- 주문번호를 모르는 체결 통보는 주문 기록이 아니라 고아 버퍼로 간다. 키는 주문번호, 값은 그 번호의 최대 누적 체결량과 최초 수신 시각이다.
- 주문이 A로 가면서 주문번호가 등록되면 해당 항목을 적용하고 삭제한다.
- To가 만료되면 대조 조회를 한다.
  - S 또는 U 주문과 매칭되면(O2) 그 주문에 주문번호를 부여하고 →A 또는 F로 보낸다.
  - 매칭되는 주문이 없으면 외부 주문(HTS 수동 주문 등)으로 본다. 포지션에 반영하고 알람을 내며, 해당 종목에 HALT를 건다.
- 버퍼에는 상한 Nb가 있다(I7). 넘쳐도 체결은 절대 버리지 않는다. 대신 모드를 SAFE로 내린다.

## 7. 매칭과 체결 반영 규칙

- O1 미확정 단일화: 계좌 전체에서 (종목, 방향)마다 S 또는 U 상태 주문은 동시에 1개까지만 둔다. 주문번호를 받기 전에는 브로커 쪽 주문과 우리 기록을 짝지을 열쇠가 (종목, 방향, 수량, 가격)뿐이라, 같은 묶음이 둘이면 대조가 모호해지기 때문이다. 같은 묶음의 두 번째 의도는 게이트에서 기한까지 기다리고, 기한을 넘기면 거절한다. 이 규칙은 I6을 강화한 것이므로, 나중에 사용자 승인을 받아 00_LAWS에 올릴지 검토한다.
- O2 대조 매칭: 주문번호가 있으면 번호로 매칭한다. 번호가 없으면 (종목, 방향, 수량, 주문 유형·가격, sentAt 이후 접수)로 1:1 매칭한다. O1 덕분에 후보는 최대 1개이고, 2개 이상이면 HALT다.
- O3 체결 반영: delta = q − cumQ로 계산한다. delta ≤ 0이면 무시한다(중복이거나 역순 도착). delta > 0이면 포지션에 반영하고 cumQ = q로 둔다. q > 수량이면 HALT다.
- O4 누적값 출처: 통보에 누적 체결량 필드가 없으면 "주문수량 − 미체결수량"으로 계산한다. 이 값은 단조 증가한다. 개별 체결량을 더하는 방식은 금지한다. 같은 통보가 중복으로 오면 두 번 더해지기 때문이다.
- O5 취소 재전송: 주문과 달리 취소는 반복해도 안전하다(이미 끝난 주문을 취소하면 거부될 뿐이다). 그래서 대조로 잔량을 확인한 뒤 최대 K회까지 재전송할 수 있다. 취소 재전송도 입장 게이트를 거친다(I2).
- O6 늦은 부활: U나 R에서 A로 넘어온 주문이 진입 주문인데, 의도가 이미 무효라면(봉ID가 지났거나, 모드가 내려갔거나, 진입 마감이 지났으면) 즉시 취소하고 →C로 보낸다. 그 사이 이미 체결된 수량은 포지션으로 인정하고, 청산 관리자가 처리한다.
- O7 재시도는 새 의도로만: 거부되거나 R이 된 뒤 다시 주문하려면, 다음 확정봉에서 새 의도키로 의도를 만든다. 같은 종목에서 연속 거부가 N회 나오면 그 종목은 당일 자동 주문을 정지한다(VI·상한가 반복 거부 대응).

## 8. 노출 계산

- 확정 보유 = Σ 반영된 매수 delta − Σ 반영된 매도 delta. 이 값은 대조로 주기적으로 검증한다.
- 진행 중 매도 = Σ (P, S, U, A, C 상태 매도 주문의 잔량). U는 전량 체결될 수 있는 것으로 계산한다.
- 매도 가능 = 확정 보유 − 진행 중 매도(I6). 매도 의도 수량이 매도 가능 수량보다 크면 의도 단계에서 거절한다.
- 진행 중 매수 노출 = Σ (P, S, U, A, C 상태 매수 주문의 잔량 × 가격). 자금 한도 검사에 쓴다.
- 대조 결과와 로컬 계산이 다르면 브로커 값을 채택하고 알람을 낸다(I11).

## 9. 설계 결론

1. 체결 통보가 REST 응답보다 먼저 오는 경쟁은 고아 버퍼가 처리한다.
2. 타임아웃 뒤 재전송하는 경로가 표 어디에도 없다. 그래서 엉뚱한 재주문은 구조적으로 불가능하다(I3, I4). 다시 주문하는 유일한 길은 새 확정봉, 새 의도키다(O7).
3. X와 R 행에 늦은 체결 칸이 있으므로 "취소했으니 포지션은 0"이라는 가정은 금지된다. 청산은 대조된 보유 수량만 본다.
4. S와 U 상태에서 받은 취소는 예약만 해 두고, 주문번호가 확정되는 순간 실행한다.
5. 전송 직전에 S를 fsync하므로, 재시작했을 때 "보냈는지 모르는" 주문은 S 기록이 있는 주문으로 한정된다.
6. 주문번호가 없는 구간에서 생기는 모호함은 O1(동일 묶음 단일화)로 원천 차단한다.
7. 상태를 믿을 수 없을 때(HALT, SAFE)는 노출을 줄이는 취소만 자동으로 하고, 새 주문은 사람이 판단한다.

## 11. TLC 검증 속성

- 탐색 범위: 전략 2, 종목 2, 주문 3, 크래시 1회, 메시지 뒤바꿈·중복·유실 허용, 외부 주문 1건
- 안전 속성 (불변식)
  - NoDoubleSubmit: 의도키마다 전송 횟수는 1 이하 (I3)
  - NoResendAfterAmbiguity: U와 R 상태 주문은 다시 전송되지 않는다 (I4)
  - CumMonotonic: cumQ는 줄지 않고, 수량을 넘지 않는다 (I5)
  - NoOversell: 모든 종목에서 진행 중 매도 ≤ 확정 보유 (I6)
  - SingleUnresolved: (종목, 방향)마다 S·U 주문은 1개 이하 (O1)
  - NoArmBeforeReconcile: 재시작 뒤 대조가 끝나기 전에는 ARMED가 아니다 (I11)
  - NoSendWhenHalted: HALT 종목에는 신규 주문 전송이 없다
- 활성 속성 (공정성 가정: 대조 조회가 결국 응답함)
  - EventuallyResolved: 모든 S와 U는 결국 A, F, X, R 중 하나가 된다
  - NoLostFill: 메시지가 잦아든 뒤 대조를 마치면, 반영된 총 체결량이 브로커의 총 체결량과 같다
