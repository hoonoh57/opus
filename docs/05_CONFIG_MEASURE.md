# 05 CONFIG / MEASURE — 설정값 목록과 실측 계획

버전: v1 (2026-11-10)

관련 문서: 00 3장 (실측값은 법칙이 아니라 L2 설정값), 01·02·03·06 미확정 사항, 04 환경 모델

## 0. 목적과 원칙

- 01~06에 흩어진 설정 기호의 유일한 목록이다. 각 문서의 미확정 표는 이 문서를 가리킨다.
- 법칙은 최악의 순서를 가정하므로 값이 틀려도 정확성은 유지되고 성능만 달라진다(00 3장). 그래서 실측 전에는 최악 가정 초기값으로 코딩하고, 실측으로 성능을 되찾는다. 코딩 착수는 실측을 기다리지 않는다(HANDOFF 7장).
- 측정이 사고를 내면 안 된다. 측정 도구는 커널이 아니며, 커널 규칙보다 더 좁게 제한한다(3장).

## 1. 값의 출처 등급

| 등급 | 뜻 | 바꿀 수 있는 사람 |
|---|---|---|
| W | 최악 가정 초기값 (설계 선택, 사실 아님) | AI 제안, 사용자 승인 |
| D | 키움 공식 문서 값 | 문서 확인 후 |
| M | 실측값 (표본 수, 측정일 함께 기록) | 실측 결과로만 |
| P | 정책값 (매매·운영 판단) | 사용자만 |

- 설정 파일(`config/limits.json`, 커밋 대상, 비밀정보 없음)은 값마다 `value`, `grade`, `source`(문서 위치 또는 실험 번호), `n`(표본 수), `date`를 가진다.
- 커널은 기동할 때 등급 W인 값의 목록을 한 줄로 경고한다. 등급 W가 남아 있으면 실전 ARMED 상향 때 사람 확인을 한 번 더 받는다.

## 3. 측정 도구 안전 규칙

측정 도구는 시스템 코드가 아니다. 코딩 착수 관문과 별개로 만들 수 있으나 아래 규칙을 구조로 지킨다.

| 번호 | 규칙 | 막는 사고 |
|---|---|---|
| MT1 | 커널과 분리된 단독 실행 프로그램. 결과는 06 형식(input·output jsonl, metrics)으로 남긴다. 06 형식의 첫 실물 검증을 겸한다 | 측정 코드가 커널에 섞임 |
| MT2 | 주문은 사람이 버튼을 누를 때마다 1건. 자동 반복·루프 기능을 만들지 않는다. 수량 1주, 1건 주문금액 상한 Amax(P), 하루 주문 상한 20건 | 측정 도구의 주문 폭주 (I3을 구조로 보장) |
| MT3 | 유량 한도 탐색은 모의 계좌, 장 종료 후, 조회 TR로만. 주문 TR로 유량을 시험하지 않는다 | 측정이 세션 리셋·제재 유발 |
| MT4 | 실전 계좌에서는 유량 한도를 탐색하지 않는다. 가동 지표(06 6장)로만 관찰한다 | 실전 리셋 |
| MT5 | 실행 전 같은 앱키를 쓰는 다른 프로그램(kiwoom-desk 등)을 종료한다. 02 단일 인스턴스 잠금을 같이 쓴다 | 토큰 상호 무효화 (D21) |
| MT6 | 모의 키와 실전 키를 섞지 않는다. 실험마다 대상 환경을 고정하고 화면에 크게 표시한다 | 모의/실전 혼동 (PM14) |
| MT7 | 비밀정보 가림은 06 2-4를 따른다 | 결과 공유 시 유출 |
| MT8 | 실험마다 결과를 한 줄로 낸다: `M04 OK rate<=N/s reject <code> session kept n=<표본>` 또는 `M04 FAIL <사유>`. 사용자는 이 줄만 채팅에 붙인다 | 긴 로그 (E08) |

### 4-1. 측정하지 않는 항목 (영구 최악 가정)

| 항목 | 이유 | 처리 |
|---|---|---|
| 주문 요청 8005가 미접수를 보장하는지 | 실전에서 일부러 8005를 일으켜야 함 | 영구 →U (01, 02 T3) |
| 주문 TR 유량 한도 | 실전 주문으로 한도를 찌르면 위험 | 조회와 같은 버킷, L0 예약분으로 처리 |
| 취소·체결 경합 응답 형태 | 일부러 만들기 어렵고 실전 손실 위험 | 01 X 행 최악 가정 유지. 가동 중 06 기록으로 수동 관찰 |
| 키움 서버 장애 동작 | 재현 불가 | 04 5장 남은 위험 |

### 4-2. 실험 순서

1. 장외 모의: M01 → M03 → M02 → M04 (토큰과 유량부터. 나머지 실험 모두 이 값에 의존)
2. 로컬: M12
3. 장중 모의: M07 → M05 → M11 → M06
4. 장중 실전 1주: M08 → M09 → M10 (MT2 적용, 여러 날)

## 5. 반영과 재검증

- 실험 결과 한 줄을 받으면 AI가 산정식으로 값을 계산해 `config/limits.json`과 이 문서 2장 등급을 고치는 수정 스크립트를 낸다.
- 실측값과 다른 최악 가정이 확인되면(예: 새 발급이 기존 토큰을 무효화하지 않음) 해당 FSM 문서의 0장 가정은 그대로 두고 "실측: 아님 (M01, 날짜)"만 덧붙인다. 정확성을 위한 장치는 남기고 성능 설정만 푼다.
- 가동 중 재검증: 06 지표가 M 등급 값의 근거를 벗어나면 경고한다. 예: 주문 응답 지연이 Tr의 절반을 넘는 비율이 하루 1%를 넘음, 장중 무음 간격이 H의 절반을 넘음, 유량 거절 발생. 경고가 이어지면 해당 실험을 다시 한다.

## 6. 자체 공격으로 고친 곳

| 공격 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 유량 한도를 한계까지 찔러 측정 | 측정이 세션 리셋·제재 유발 | 모의·장외·조회 TR, 계단식, 첫 거절 중단 (MT3, M04) |
| 모의 계좌에서 주문 타이밍 측정 | 모의 체결은 흉내라 값이 무의미 | 실전 1주 수동 (M08) |
| 측정 도구에 자동 주문 반복 | 측정 도구가 주문 폭주의 새 경로 | 버튼 1건, 반복 기능 없음, 하루 상한 (MT2) |
| 표본 수십 건으로 p99 산정 | 꼬리값 과소평가 | 관측 최대 × 배수, 표본 수 기록, 가동 중 재검증 (5장) |
| 측정 중 kiwoom-desk가 같은 키로 실행 | M01 결과 오염, 토큰 경합 | MT5 |
| 위험한 항목까지 확인하려 함 | 확인 실험이 사고 | 측정하지 않는 항목 (4-1) |
| 실측이 끝나야 코딩 착수 | 관문 지연 | 최악 가정 초기값으로 코딩, 실측은 성능 회복 (0장) |
| 실측이 최악 가정을 부정하면 장치 제거 | 드문 경우에 정확성 상실 | 장치 유지, 설정만 완화 (5장) |
| 정책값을 AI가 실측값처럼 정함 | 매매 판단을 AI가 대신함 | 등급 P, 사용자만 결정 (1장) |
