# 07 STRATEGY LAB — 전략 실험실

v1, 2026-11-10. 주문을 내지 않는다(커널 01~06과 독립, 병행 가능). 상위 전제는 HANDOFF 2장·3장.

## 0. 목적과 유일 지표

- 이 앱의 주 역할은 수익 로직의 작성과 검증이다. 실측·관제는 보조 기능이다.
- 진입할 자리에서만 진입하고 나머지는 걸러, 기준 전략 B0 대비 수익률을 올린다.
- 유일 KPI: 같은 사례 묶음에서 비용 차감 후 순수익률의 합 Σnet. 버전업 판단은 Δ = Σnet(도전자) − Σnet(챔피언).
- 개선 과정(전략 버전, 근거 사례, 개선과제, 채택·기각 결정)은 모두 저장소 파일로 남긴다. 세션이 바뀌어도 파일만 읽으면 이어진다.

## 1. 입력: 포착 리스트

- 출처: 사용자의 성과검증 앱이 지정한 조건식·일자·시각으로 뽑은 포착 종목 리스트. 실험실은 조건식을 다시 계산하지 않는다.
- 필수 열: 일자(YYYYMMDD), 시각(분 단위), 종목코드. 선택 열: 종목명, 포착가, MFE, 조건식.
- 포착 기준가 = 포착 분봉의 종가(예: 09:05 포착 → 09:05봉 종가, 09:05:00~09:05:59). 키움 REST 1분봉 시각은 봉 시작 시각이다(L02R 확정 2026-11-10).
- MF1 (확정 2026-11-10, L02R 5/5 오차 0): MFE% = (포착봉 다음부터 15:30까지 1분봉 종가의 최고값 ÷ 포착봉 종가 − 1) × 100. 고가가 아니라 종가, KRX 정규장만(시간외 제외). 성과검증 앱의 '기간 내 최고수익률'(7시간 = 장 마감)과 같다.
- 고MFE = MF1 ≥ 10%. 평가 전용 라벨이며 진입·청산 수식에서 읽지 않는다(미래 데이터).
- 입력 포착가는 포착봉 종가와 다를 수 있다(2026-11-10: 5종목 중 2종목 10원 차이). MFE와 capPct는 포착가가 아니라 포착봉 종가로 계산한다.
- 사례 묶음 = (조건식 이름, 조건식 버전, 포착 시각 범위, 일자 범위). 조건식을 바꾸면 새 사례 묶음이며 기존 묶음과 섞지 않는다(CS1).
- 입력은 콘솔 포착 입력 탭(붙여넣기). 원본은 `lab/captures/capture_YYYYMMDD.csv`(자동 커밋), L01용 사본은 `measure/lab-data/inbox/`(커밋 안 함). 연결 확인은 L01, MFE 재현 확인은 L02R.

## 2. 데이터

- 정밀 사례: 틱 캔들(B0 기준 60~120틱). 틱은 증권사가 최근 1달만 주므로 정밀 구간은 최근 1달 + 축적분.
- 참고 사례: 1분봉(약 1.5년). 신호 흐름 확인용 근사. 정밀과 참고 결과는 항상 따로 표시하고 합산하지 않는다(DT1).
- LB1: 매일 장 마감 뒤 그날 포착 종목의 틱만 저장한다. 하지 않으면 정밀 구간이 영원히 1달에 머문다.
- 캐시: `measure/lab-data/candles/<tf>/<code>/<date>.jsonl`. 한 번 받은 날짜는 다시 쓰지 않는다(DT2). 수집 속도는 05 설정값(M04 결과)을 따르고 커널과 같은 앱키 동시 사용 금지(MT5).

## 3. 세 가지 모드

| 모드 | 입력 | 출력 |
|---|---|---|
| 당일 D | 오늘 포착 리스트에서 종목 선택 | 차트: 캔들, Supertrend·JMA·Momentum(80), 챔피언·도전자 BUY/SELL, 포착 시각 선, MFE 선. 매매 표 |
| 기간 P | 일자 + 시각 선택 | 그 시점 포착 종목 표(종목별 순수익률, 고MFE 여부) → 행 클릭 시 D와 같은 차트 |
| 구간 R | 시작일, 종료일, 전략 버전(들) | 전 사례 자동 실행 → 실행 기록, KPI 표, 개선과제 후보(7장) |

R은 버튼 하나로 끝까지 돈다. 사용자는 결과 표와 차트만 본다.

## 4. 체결·비용 모델

- FM1: 신호는 확정봉(append로 직전 봉 확정)에서만. 체결은 다음 봉 시가 + 슬리피지 s틱. 신호봉 종가 체결 금지(미래 참조).
- FM2: 청산도 FM1과 같다. 손절·익절 가격 도달형 규칙은 그 봉 안 도달 시 규칙 가격 + 슬리피지.
- FM3: 강제 청산 시각 Tx(오버나이트 금지). 
- FM4: 비용 = 매도 시 증권거래세 0.20% + 매수·매도 수수료 f + 슬리피지. 모든 KPI에 차감.
- FM5: 사례당 동시 포지션 1개. 재진입 허용 여부는 전략 버전이 정한다.
- FM6: VI 등으로 다음 봉이 없거나 비정상이면 그 매매는 '체결 불확실'로 표시하고 KPI에 포함하되 따로 센다.

## 5. KPI와 버전업 규칙

- K1(유일 판정): Σnet = 사례별 순수익률의 합. 매매가 없던 사례는 0. 손실 매매를 막으면 오르고, 수익 매매를 놓치면 내려간다. 매매 0건이 최적이 되는 함정이 구조적으로 없다.
- 참고 지표(판정에 쓰지 않고 표시): 매매 수, 승률, 손익비, 최대 연속 손실, 막은 손실 건·합, 놓친 수익 건·합, 고MFE 사례의 순수익률 합.
- VU1: 비교는 같은 사례 묶음, 같은 캔들, 같은 비용 설정에서만.
- VU2: 개선과제를 발견한 구간(발견 구간)과 겹치지 않는 구간(확인 구간)에서도 Δ>0이어야 채택. 발견 구간에서만 좋아지면 기각.
- VU3: 채택 판정은 정밀 사례 우선. 정밀 사례 수가 최소 n 미만이면 '보류'로 두고 누적 뒤 재판정.
- VU4: 설정을 조금 바꿔 Δ 부호가 뒤집히면 최고점 대신 주변까지 고르게 좋은 값을 고른다(HANDOFF 3장).
- VU5: 채택·기각·보류 모두 `lab/decisions.jsonl`에 남긴다. 기각된 시도도 같은 가설 반복을 막는 자료다.

## 6. 전략 버전

- `lab/strategies/<id>/v<N>.json`: 수식관리자(12장) 형식의 전략 정의(캔들, 파라미터, 지표, 진입·청산 수식). 파일 안 `reason`에 무엇을, 어떤 개선과제 때문에, 어떤 실행 기록을 근거로 바꿨는지 적는다.
- SV1: 커밋된 버전은 고치지 않는다. 바꾸려면 v<N+1>을 만든다.
- SV2: 실행 기록마다 전략 내용 해시를 남기고, 해시가 다르면 실행을 거부한다.
- SV3: 현재 챔피언은 `lab/champion.json` 한 곳에만 적는다.
- SV4: 계산기는 kiwoom-desk 계약(`reset(allBars)`, `update(bars, append|replace)`)을 따르고 지표는 kiwoom-desk `addons/chart-indicators/plugins`의 계산식을 출처 커밋과 함께 가져온다. 차트와 구간 분석은 같은 코드를 쓰며 패리티 검사로 확인한다.

## 12. 수식관리자 (전략 CRUD)

전략은 코드가 아니라 수식 정의 파일이다. 사용자가 화면에서 만들고, 고치고, 복제하고, 바로 구간 분석에 건다.

### 12-1. 정의 파일 형식

`id`, `version`, `name`(예: 기준전략_V1), `status`(draft/frozen/archived), `parent`(id/vN), `reason`, `candle`(tick n 또는 min n), `params`(이름별 value·min·max·step), `indicators`(이름 → 지표 함수 + 파라미터 이름), `entry`(수식 1개), `exits`(순서 있는 목록, 먼저 참인 것으로 청산), `reentry`.

### 12-2. 수식 언어

- 연산: 사칙, 비교, and/or/not, 괄호. 숫자와 파라미터 이름.
- 변수: open, high, low, close, volume, netPct(현재 보유 순수익률, 비용 차감), barsInPos, minSinceCapture, gapPct, capPct(포착 기준가 대비).
- 지표 값: 이름.필드(예: st.dir, st.line, jma, mom). 
- 함수: turnUp(x), turnDown(x), crossUp(a,b), crossDown(a,b), ref(x,n), highest(x,n), lowest(x,n), avg(x,n), min(a,b), max(a,b), abs(x).
- FX1: 전용 파서로 계산한다. eval·Function 금지.
- FX2: ref·highest 등의 n은 0 이상의 상수만. 미래 참조는 문법에서 불가능하다. 수식은 확정봉만 본다(FM1).
- FX3: 모르는 이름, 타입 오류, 상수가 아닌 n은 저장 단계에서 거부하고 위치를 표시한다.
- FX4: 저장 전 표본 사례로 시험 실행해 신호 수를 보여준다. 신호 0건이어도 저장은 되나 경고한다.

### 12-3. 지표 함수

- 지표는 코드로 구현된 목록에서 고른다: supertrend(period, mult), jma(len, phase, power), momentum(period), ema(n), sma(n), atr(n), vwap(), tickStrength(n). 새 지표는 코드 추가(L 단계 등록)로만 늘어난다.
- 지표 구현은 kiwoom-desk 계산식과 패리티 검사(SV4)를 통과해야 목록에 오른다.

### 12-4. CRUD 규칙

- C: 새 id 또는 기존 버전 복제. 복제본은 parent를 남긴다.
- R: 목록, 버전 계보, 버전 간 차이(파라미터·수식 줄 단위).
- U: frozen 버전은 고칠 수 없고 저장하면 v<N+1>이 된다. reason 필수. draft는 덮어쓸 수 있으나 실행 기록이 생기면 자동으로 frozen.
- D: archived 표시만 한다. 실행 기록이 참조하므로 파일을 지우지 않는다.
- 저장은 콘솔이 해당 파일만 커밋한다(ledger와 같은 방식).
- 챔피언 교체는 수식관리자에서 하지 않는다. 구간 분석의 VU 판정과 decisions.jsonl로만 바뀐다(SV3).

### 12-5. 파라미터 탐색

- params의 min·max·step 범위에서 격자 실행을 구간 분석에 건다. 결과는 파라미터별 Δ 표와 열지도로 보이고, VU4에 따라 최고점 대신 주변까지 고르게 좋은 값을 고른다.
- 탐색 결과에서 고른 값은 새 버전(reason에 탐색 실행 id)으로만 저장된다.
