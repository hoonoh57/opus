# 00 LAWS — 구조와 불변식

이 문서는 시스템의 최상위 법칙이다. 새 기능이 이 법칙과 충돌하면 법칙이 아니라 기능을 바꾼다.

## 1. 4층 구조

| 층 | 내용 | 변경 빈도 |
|---|---|---|
| L0 법칙 | 불변식 I1~I12 | 영구 |
| L1 커널 | 브로커 추상 포트(query / subscribe / submit / cancel / reconcile), 이벤트 저널, 모드 상태기계, 입장 게이트, 주문 상태기계 | 거의 없음 |
| L2 어댑터 | 키움 REST/WS 매핑, TR 코드, 오류 코드를 커널 사건으로 변환, 한도 수치 | API가 바뀔 때마다 |
| L3 소비자 | 창(UI), 전략 플러그인, 백테스트, Strategy Lab | 수시 |

의존 방향 규칙:
- 허용: L3 → L1, L2 → L1
- 금지: L1 → L2, L1 → L3, L3 → L2 (소비자가 키움을 직접 호출하면 안 됨)
- 증권사가 바뀌면 L2만 교체한다.

## 2. 불변식

| 번호 | 법칙 | 막는 사고 |
|---|---|---|
| I1 | (계좌, 환경)당 인증 소유자 1개, 세션 1개. `.env`를 읽는 곳은 커널뿐이다. | 인증 경합, 모의/실전 혼선 |
| I2 | 모든 외부 호출은 단일 입장 게이트를 통과한다. 우회 경로는 0개다. 게이트 속도 ≤ 한도 × 안전계수. | 유량 위반 → 리셋 |
| I3 | 주문은 의도키(전략 + 종목 + 봉ID + 방향)당 최대 1회 전송한다. 자동 재전송은 어떤 경우에도 금지한다. | 주문 폭주, 중복 체결 |
| I4 | 결과가 모호하면(타임아웃 등) 재전송하지 않는다. UNKNOWN 상태로 두고 대조 조회로만 해소한다. | 엉뚱한 재주문 |
| I5 | 체결은 (주문번호, 누적체결량)의 단조 증가분만 반영한다. 같은 통보가 중복으로 와도 무해하다. | 순서 역전, 이중 반영 |
| I6 | 매도 가능 수량 = 확정 보유 − 진행 중 매도. (전략, 종목, 방향)당 열린 주문은 1개 이하다. | 과매도 |
| I7 | 모든 큐에 상한이 있고 모든 요청에 기한이 있다. 넘치면 BUSY로 명시적으로 거절하고 조용히 쌓지 않는다. | 자원 고갈 |
| I8 | 생산자는 소비자를 기다리지 않는다. 상태형 데이터(시세, 호가)는 최신값만 보낸다. 사건형 데이터(주문, 체결)는 별도 차선으로 유실 없이 전달한다. | UI 멈춤, 체결 유실 |
| I9 | 상태 칸 하나당 쓰기 주체는 1개(액터)다. 공유 가변 상태는 금지한다. | 경합 일반 |
| I10 | 모드 격자는 SAFE < DEGRADED < ARMED다. 하향은 자동, 상향은 대조 완료 후에만 한다. HALT 해제는 사람만 한다. | 사고 확산 |
| I11 | 로컬 상태는 저널을 투영한 결과이고, 진실은 브로커 대조 결과다. 재시작하면 대조가 끝나기 전까지 ARM을 금지한다. | 재시작 후 유령 포지션 |
| I12 | 순서는 브로커 순번이나 거래소 시각으로 판단하고, 타임아웃은 단조 시계로 잰다. 벽시계는 쓰지 않는다. | 시각 역전 |

## 3. 법칙 운용 규칙

- 모든 설계 결정, 코드 모듈, 테스트는 자신이 지키는 불변식 번호를 표기한다.
- 불변식을 추가하거나 바꾸려면 사용자가 승인해야 하고, `HANDOFF.md` 변경 기록에 남긴다.
- 실측해야 하는 값(유량 한도, 토큰 수명, 응답 순서 분포)은 법칙에 넣지 않고 L2 설정값으로 둔다. 법칙은 최악의 순서를 가정하므로, 실제 값이 달라도 정확성은 유지되고 성능만 달라진다.
